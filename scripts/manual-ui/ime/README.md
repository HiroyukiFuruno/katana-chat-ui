# 実日本語IMEの隔離受入

`probe.py` は実IBus/Mozcの未確定・変換・確定・取消と、hostのdraft/action traceを照合する。単体の合成IMEイベントやUnicode貼付は使わない。最終文字列の検査と画像の目視は別々に確認する。

Linuxは既存のnative host buildを`kcu-v010-linux-target`へ準備した上で、Dockerfileのimageを`kcu-ime-linux-arm64:local`としてbuildし、repo直下から次を実行する。

```sh
rtk proxy python3 scripts/manual-ui/ime/run-background.py tmp/verification/ime-new-run
```

新しいartifact directoryだけに書込み、hostのDISPLAY/X socket・clipboard・networkを渡さない。専用uidのXvfb上で操作する。UTF-8 localeを必須とする。実行前後のJSONとnative bus log、各段階のapp画像・候補windowを含むscene画像を保存する。

macOSの`macos-probe.swift`はGitHub Actionsの専用runnerでだけ実行する。Release workflowの`verify_native_ime=true`は公開処理を無効にして診断だけを実行する。権限不足はexit77で未検証を記録する。ローカルではtypecheck/compileだけを行い、実行しない。

OCRは初期placeholderから本文行の位置を取得し、候補windowの別行を除いて本文を完全一致で検査する。純粋な行選択・重複拒否の単体検査は`macos-ocr.swift`と`test-macos-ocr.swift`を一緒にcompileして実行でき、アプリ・IME・入力ソースには触れない。native probeのtypecheck/compileには`macos-ocr.swift`、`macos-native-ack.swift`、`macos-input-menu.swift`、`macos-probe.swift`を渡す。

`macos-reference.swift`は標準`NSTextView`を同じrunner・入力列で操作する比較器。実際の`setMarkedText`・`insertText`・`unmarkText`を記録し、runner/入力手順とKCU adapterの境界を切り分ける。比較器の成功をKCUの受入として数えない。これもローカルでは起動せず、CIでKCU各hostと同じ試験を行う。

比較器は`macos-ime-state.swift`と一緒にcompileする。実際の本文とmarked状態を受動観測し、同じ確定状態が連続して確認された時だけ記録する判定を`test-macos-ime-state.swift`で単体検査する。この単体検査はAppKitを起動しない。

macOSでは入力欄へfocusしてから日本語入力方式を選択し、空入力欄の表示とfocusを再確認する。`KCU_IME_ACTIVATION_KEY`で追加の「かな」キーを送る条件と送らない条件を比較し、workflowで使用条件を明示する。制御文字の挿入が発生した場合も初期化前からのtrace差分で失敗にする。`nihongo`の未確定表示、Spaceによる変換、Returnによる確定、続く`tesuto`のEscape 2回による取消を検査する。送信key codeと時刻、標準入力欄のmarked状態も記録する。日本語のUnicode文字列を直接入力してIME成功に見せる処理は使わない。

CopilotのローカルBYOK受入はCopilot Freeのcloud quotaの証明ではなく、Linuxの実IME受入はmacOS固有の受入の代替ではない。

macOS診断では、同じ標準NSTextViewについて瞬時のdown/upと50ms押下を比較する。押下時間は入力操作の条件であり、画面準備の固定待ちやtimeout延長ではない。各keyのdown/up時刻を保存し、本文完全一致・確定一回・未確定draft非反映・誤送信なしの判定は共通とする。瞬時tapの失敗も保持し、成功に置き換えない。

押下時間はThreadの待機で維持し、送出直前の単調時計から実測する。RunLoopの早期returnや、生成直後のCGEvent timestampが0のままになる場合を成功証拠に使わない。実測が指定押下時間を下回った場合は検証を失敗にする。

`ime_reference`は同じeframe依存の標準TextEdit比較器で、実ImeCommitとraw Textを区別して記録する。TextEditの内部bufferへpreeditが入ることをKCUの確定draftと混同しない。比較器の成功はKCU hostの合格ではない。通常の`cargo run`は`default-run`で従来のmanual-host-eguiを起動する。

標準AppKit比較器はkeyDown処理後に子アプリ自身のNSTextInputContextを観測し、親probeのTIS選択と区別する。`KCU_REFERENCE_CONTEXT_SOURCE`による子context選択と、`KCU_REFERENCE_EXTRA_RETURN=1`による追加Returnは比較器専用の診断であり、通常KCU hostの受入経路へ適用しない。追加Returnは、最初のReturn処理後も実際にmarked状態だったと子traceで確認した場合だけ送る。通常1 Returnの失敗はそのまま保存する。

`KCU_IME_ACTIVATION_METHOD=shortcut`は専用runnerのUS入力方式から実Control+Spaceを送出し、日本語方式への切替を確認してから入力する。modifierのdown/upも送出し、API選択だけの比較対照と区別する。切替できない場合はblockedとして失敗し、文字列入力へ進めない。

Native10の標準NSTextViewでは、1回目のReturn後もmarkedで、2回目にinsertTextとmarked解除が発生し、確定一回・取消保持まで通過した。この実証に基づく`KCU_IME_CONFIRMATION=observed`は最初のReturnのkeyUp処理完了を子アプリで確認し、native marked状態が残る場合だけReturnを一回追加する。本文画像だけで処理完了を推測しない。予期しないcommand・重複確定・誤送信は許可しない。最終条件は日本語draftの確定一回と取消時保持であり、押下回数と確定回数を混同しない。従来1 Return試験の失敗記録も保持する。

`macos-native-observer.m`は専用CIで対象バイナリ名が一致する子プロセスにだけ読み込む検証補助。NSAppを早期生成せず、起動完了と親の要求を待って、同じwindow内の実入力clientが選択している入力方式を観測する。検証補助からactivateやsource選択を行わない。元の`sendEvent:`を一度だけ呼び、戻った後のkeyUp・native marked状態を別JSONLへ記録する。`insertText`、`setMarkedText`、`unmarkText`やhost commandを合成しない。観測用libraryは製品crateへ含めず、ローカルではcompileだけを行い、ロードしない。

親は準備完了のselected source・client/window一致・初期未確定状態なしを要求し、preedit/変換中はnative marked=true、確定・取消後はfalseを照合する。`macos-native-ack.swift`と純粋テストは古い通知、別window、keyDown、不正な型、未完行と壊れた完了JSONを区別する。OS処理完了を確認できなければ追加キーを推測で送らず失敗する。

Native12ではsource IDとclient/window一致の後も、標準入力欄を含む4caseが英字入力になった。source IDだけを実IME準備の証拠にしない。`KCU_IME_ACTIVATION_MENU=1`は専用runnerの実システム入力メニューからHiraganaを選び、AX treeを保存する比較手順である。所有プロセス・role・identifier/titleを限定し、Hiragana候補は開いた入力メニューの子孫だけに限定し、enabledでない候補や曖昧な候補は押さず失敗する。private APIや固定待機での補正は行わない。取消後はmarked状態が不正でも診断画像と実marked rangeを保持する。

Native14では入力status itemを一意化できたがAXPressが失敗し、実IME入力前に停止した。次の比較は同じAX要素のenabledと可視screen内boundsを確認し、その中心へ専用runnerの実マウスdown/upを送る。クリック座標・対象属性・広告されたAX actionを保存する。入力方式の文字列やcomposition callbackは合成しない。
