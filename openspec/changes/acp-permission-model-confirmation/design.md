## Decisions
ACP SDK型はtransport境界で読み、permission UIにはneutralな文字列を渡す。承認対象のtitleと提供済みtext/path/raw入力の操作情報を失わず表示し、HTMLとして実行しない。情報が省略された場合に操作内容を推測しない。長い内容はviewport内で確認できるようにし、buttonsと既存modal routingを壊さない。

permissionのcontext subtreeは表示と計測で共有する。runtimeが実描画と同じKUC rendererのdocument node boundsを取得し、unclipped leaf位置からscroll content高を求める。文字数からの推測幅やcomposer専用rasterizerによる別計測は使わない。提供optionとcancelの領域を確保し、長い内容だけをmodal内でscrollする。

model変更はSetSessionConfigOption成功応答のconfig_optionsを既存SessionConfigOptionsUpdatedと同じ経路へ流す。hostが送った値を先に確定せず、agentの返すcurrent_valueを採用する。既存ConfigUpdatedの通知互換性と失敗時の保持を維持する。agentがInvalidRequest・MethodNotFound・InvalidParamsを返した場合は、拒否理由を利用者へ返し、選択済みmodel・provider readiness・保留中permission・実行中streamを変更しない。SDKは応答喪失もInternalErrorへ変換しremote errorと出所を区別できないため、この3種類だけを拒否として扱い、InternalError・RequestCancelled・AuthRequired・Other等は従来どおり失敗としてproviderをfail closedにする。

historyから復元するACP modelは、SetSessionConfigOptionのenqueueを完了とみなさない。要求中は保存済みmodelを表示したままproviderをMissingにし、該当config_idの成功応答を待つ。成功応答後も、agentのconfig_optionsに含まれるcurrent_valueが要求modelと一致した場合だけ復元状態を解除し、agentが確定したmodelでproviderをConfiguredにする。要求拒否または別modelの応答では明示理由を付けてBlocked/Missingを維持し、保存済みmodelを変えない。Blocked後の利用者によるmodel選択も同じ確認応答までMissingのまま待つ。直接同期応答を持つKatanAgentの選択動作は維持する。

## Verification

providerごとの会話文脈はAcpHostBridgeが保持し、manager全体の消費boolや全bridge一括clearは使わない。選択・bind・送信の際に、そのtransportの確定済みmessage位置より後を既存のescaped data blockへ変換する。prompt enqueue後は今回のuser/assistant位置を保留し、Finishedでのみ確定する。Stopのenqueueは確定条件にせず、Failed/Unavailable/同期送信失敗では保留位置を破棄して次の送信で文脈を再計算する。会話の新規作成・復元ではtransportを破棄して位置を0から始める。snapshot差し替えで現在のmessage数が確定位置より短い場合も位置を0へ戻し、履歴の欠落や範囲外参照を起こさない。model設定・permission・KatanAgentの状態はこの位置と独立に維持する。

切替先への文脈、同一providerの重複禁止、A→B→Aの差分、失敗・取消待ち・終端・会話境界を恒久回帰にする。unit用cat fixtureはslotの所有とcontext形成だけに用い、実wireやagent受理の証拠とはしない。実ACP通信は既存の無料設定と独立したtraceで確認し、新規認証や課金を要求しない。
先に失敗するunit契約、host projection/persist、実KUC frame/inputのpermission回帰を追加する。IT/E2Eでmock serverは使わない。現行SDKの実Codex model/history probe、通常の全体check/release-checkで受け入れる。
